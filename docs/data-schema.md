# Паспорт данных Сверки

Схема обмена и экспорта имеет версию `1.0`. Типы и ограничения предметных полей заданы в [JSON Schema](extractor.schema.json), HTTP-форматы — в [OpenAPI](openapi.yaml). Каждая загрузка создаёт собственный документ. ID извлекателя локальны для одного ответа и после импорта заменяются серверными. `corpus_id` обозначает имя файла корпуса, например `D019`.

| Сущность | Состав и связи |
|---|---|
| Документ | Серверный ID, оригинальное имя, идентификатор корпуса, время загрузки, режим, статус и причина сбоя. PDF хранится на диске. |
| Публикация | Название, год, DOI, авторы, признак включения и причина исключения. Одна запись на PDF. |
| Конфигурация | Вариант RAG, способ поиска, модели и версии, разбивка на сегменты, индекс, хранилище, `top_k`, reranker, генератор, стратегия контекста. Размер сегмента и перекрытие указаны в `chunk_unit`. |
| Датасет и задача | Датасет описывается именем, версией, сплитом, языком и областью. Задача описывается типом. Результат ссылается на обе записи. |
| Эксперимент | Протокол, baseline, вычислительное оборудование, задержка в мс, токены на запрос и размер выборки. |
| Результат | Ссылки на конфигурацию, эксперимент, датасет, задачу. Метрика, вариант, направление, `metric_k`, агрегация, выборка, исходное значение и единица, нормализованная пара, статус извлечения и происхождение. У цитируемых результатов предметные ссылки могут быть пустыми. |
| Источник | Привязка к сущности или конкретному полю, страница с 1, дословный фрагмент, таблица и ячейка или рисунок, способ сверки. При наличии `bbox` координаты задаются в долях видимой страницы. |
| Замечание | Код проверки, описание, серьёзность, ID связанных результатов и источников. Замечания уровня документа могут ссылаться на непрочитанные страницы в описании. |

## Шкалы и проверки

`raw_value` и `raw_unit` сохраняют запись из PDF. `reported_value` хранит число до пересчёта. Явные доли и проценты приводятся к `fraction`, поддерживаемые единицы времени — к `ms`. Неизвестные сведения представлены пустыми полями или `null`, допустимый ноль сохраняется. Проверка диапазона применяется к известному варианту ограниченной метрики при установленной шкале.

Замечания включают отсутствие k, неизвестную единицу или шкалу, отклонение от известного диапазона, необходимость сверки источника, отсутствие обозначения цитируемой публикации и baseline, который не удалось сопоставить или нормализовать. Для такого baseline поле `baseline_value` остаётся пустым, а замечание связывает обе записи. Результаты с замечаниями сохраняются. Некорректные типы, ссылки и координаты блокируют импорт документа целиком.

При сравнении API оценивает задачу, датасет, версию и сплит, определение метрики, cutoff `k`, шкалу, агрегацию и протокол оценки. Известное различие по обязательному критерию даёт `not_comparable`; недостаток сведений без известного различия — `insufficient_information`. Числовая разница появляется при `comparable`, когда доступны оба нормализованных числа. Эти критерии перенесены из RAG-части кейса; условия области тонкоплёночных солнечных элементов к этому проекту не применяются.

`#groups` показывает результаты разных публикаций только при совпадении полного набора RAG-критериев. Разные конфигурации не сливаются и остаются видны внутри группы. Граф связей между публикациями не строится.
