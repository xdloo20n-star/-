# Запуск Сверки в Docker

## Локальный запуск

Выполните из корня репозитория с Docker и Docker Compose v2:

```bash
docker compose up --build -d --wait
docker compose ps
curl -fsS http://127.0.0.1:8080/healthz
```

Сверка доступна на `http://127.0.0.1:8080/`. Go-бинарник содержит веб-интерфейс из `web/`. Контейнер по умолчанию запускает `extractor/main.py` и использует Poppler и Tesseract с английской языковой моделью `eng`. Журнал API и сообщения об ошибках обработки доступны через `docker compose logs -f sverka`.

Создайте `.env` в корне репозитория или задайте переменные в окружении перед запуском Compose. Для контейнера действуют следующие значения:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `SVERKA_BIND_IP` | `127.0.0.1` | Адрес хоста, на котором Compose публикует порт. |
| `PORT` | `8080` | Порт API внутри контейнера и опубликованный порт хоста. Укажите число от 1 до 65535. |
| `HOST` | `0.0.0.0` | Адрес прослушивания в сети контейнера. |
| `DATA_DIR` | `/data` | Каталог данных в контейнере и точка монтирования тома `sverka-data`. |
| `CORS_ORIGIN` | `http://localhost:5173` | Точный origin отдельно запущенного фронтенда. Для встроенного интерфейса можно задать `CORS_ORIGIN=`. |
| `MAX_PDF_BYTES` | `33554432` | Максимальный размер PDF в байтах, по умолчанию 32 МиБ. |
| `EXTRACTION_MODE` | `python` | Режим обработки. Для синтетических результатов задайте `mock`. |
| `EXTRACT_TIMEOUT` | `5m` | Максимальное время обработки одного задания. |
| `PYTHON_BIN` | `python3` | Исполняемый файл Python внутри контейнера. |
| `PYTHON_SCRIPT` | `/app/extractor/main.py` | Путь к скрипту внутри контейнера. |
| `TESSERACT_BIN` | `tesseract` | Исполняемый файл Tesseract внутри контейнера. |
| `OCR_LANG` | `eng` | Языковая модель Tesseract. Для другого языка установите соответствующий пакет в образ. |

Переменные `HOST` и `DATA_DIR` заданы образом. Для изменения адреса на хосте используйте `SVERKA_BIND_IP`. При изменении пути внутри контейнера через конфигурацию сервиса перенесите точку монтирования на тот же путь.

При запуске сервер проверяет `PYTHON_SCRIPT` и `PYTHON_BIN`, если включён Python или в базе остались задания этого режима. После `SIGTERM` воркер прекращает брать задания из очереди и даёт текущему заданию до 10 секунд для завершения. Если обработка прервана, воркер получает ещё до 5 секунд на запись статуса.

## Развёртывание за прокси

Для обратного прокси на том же хосте оставьте `SVERKA_BIND_IP=127.0.0.1` и направьте запросы к `http://127.0.0.1:8080` или к выбранному `PORT`. Передавайте пути `/`, `/api/v1/` и `/healthz` без переписывания. Настройте TLS и ограничение доступа на прокси, поскольку API принимает и выдаёт PDF без аутентификации. Лимит тела запроса прокси должен учитывать `MAX_PDF_BYTES` и дополнительные 64 КиБ на multipart-обёртку.

Если прокси находится на другом хосте, задайте `SVERKA_BIND_IP` равным IP нужного интерфейса и ограничьте доступ к опубликованному порту адресом прокси. Для отдельного фронтенда задайте `CORS_ORIGIN` равным его публичному origin, например `https://ui.example.org`, без пути и завершающего `/`.

## Данные и резервное копирование

Именованный том `sverka-data` хранит SQLite (`sverka.sqlite` или существующий `papertrace.sqlite`) и PDF в `pdf/`. Обычный `docker compose down` сохраняет том. Используйте один экземпляр Сверки на том и сохраняйте имя проекта Compose при обновлении. Контейнер работает с UID и GID `10001`. При замене тома на каталог хоста заранее создайте каталог и обеспечьте этому пользователю чтение и запись в него и в существующие файлы данных.

При запуске Сверка удаляет незавершённые временные загрузки и файлы вида `doc_*.pdf`, созданные API, для которых в SQLite нет задания.

При переходе SQLite с версии 1 или 2 на версию 3 сервер проверяет сохранённые числа, `k` и ссылки на дубликаты, обновляет связанные baseline и индекс замечаний. Миграция проходит в одной транзакции при запуске. Для отката на приложение, которое читает только версии 1 и 2, восстановите резервную копию до обновления.

Остановите сервис перед архивированием и сохраните весь `/data`, включая оригиналы PDF и файлы SQLite WAL, если они остались после остановки. Храните архив вне тома. В примере имя архива должно быть свободно:

```bash
docker compose stop sverka
(umask 077; set -C; docker compose run --rm --no-deps -T --entrypoint tar sverka -czf - -C /data . > sverka-data.tar.gz)
docker compose start sverka
```

Для восстановления используйте пустой том. Например, выберите новое имя проекта Compose, распакуйте архив и запустите восстановленный сервис:

```bash
docker compose -p sverka-restored run --build --rm --no-deps -T --entrypoint tar sverka -xzf - -C /data < sverka-data.tar.gz
docker compose -p sverka-restored up -d --wait
```

Перед запуском остановите прежний экземпляр или назначьте восстановленному сервису свободный `PORT`.
