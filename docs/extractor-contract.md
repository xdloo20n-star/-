# Сверка. Контракт Python-извлекателя

Python принимает один PDF из области RAG и возвращает библиографию, конфигурации, наборы, задачи, эксперименты, результаты и места в источнике. Go управляет очередью, проверяет связи, нормализует результаты и формирует замечания. Версия обмена — `1.0`. [JSON Schema](extractor.schema.json) · [Синтетический пример](examples/extractor-mock.json)

## Запуск из Go

```bash
python3 extractor.py --pdf "/path/to/file.pdf"
```

Go запускает настроенный скрипт отдельным процессом, передаёт абсолютный путь одним аргументом и задаёт таймаут. При успехе код выхода — `0`, stdout — ровно один JSON-объект в UTF-8, `schema_version="1.0"` и `extraction_mode="python"`. Диагностика и прогресс идут в stderr. При фатальной ошибке процесс возвращает ненулевой код, а Go помечает задачу как `failed`. Имя файла на диске сгенерировано сервером. Идентификатор вроде `D019` Go берёт из исходного имени загрузки при импорте корпуса, если оно соответствует корпусной нумерации.

## Сущности и ссылки

- `document` содержит число страниц и `unreadable_pages` с номерами страниц, которые не удалось прочитать. `publication` — библиография текущего PDF и решение `in_scope`. Для статьи вне области верни `in_scope=false` с `exclusion_reason` и пустыми массивами предметных сущностей. Если невозможно прочитать документ и определить его содержание, верни ошибку процесса.
- ID уникален в пределах своего типа в одном ответе, например `config_id` среди `configurations`. Go проверяет все ненулевые ссылки и при сохранении заменяет локальные ID серверными. У первичного результата обязательны ссылки на эксперимент, конфигурацию, датасет и задачу. Сущность с известным ID может иметь неизвестные описательные поля. Если статья сообщает об эксперименте без названия датасета, создай отдельную запись с `dataset_name=null` для этого контекста, сохранив факт отсутствия названия.
- `result_origin=primary` охватывает и baseline, который авторы сами переоценили. Для `cited` заполни `cited_publication_id` обозначением из статьи, например `[12]`, если оно установлено. Это текстовая ссылка, поэтому отдельная запись публикации для неё не нужна. Связи с экспериментом, конфигурацией, датасетом и задачей у цитируемого числа могут быть `null`.
- Неизвестное значение обязательного nullable-поля — `null`. Необязательные поля можно опускать или передавать как `null`. Сохраняй значимый ноль, в том числе `top_k=0`. `top_k` описывает конфигурацию, `metric_k` — целочисленный cutoff метрики. При `metric_k_applicability=applicable` неизвестный cutoff остаётся `null`. Дробный порог вроде `OC@0.8` сохраняй в определении или варианте метрики.

## Значения и источники

- Каждое число привязано к своей метрике и эксперименту. `raw_value` сохраняет запись из PDF, например `"22.27"`, `"−3.2"` или `"12–15"`. `reported_value` — числовой разбор одного числа, без пересчёта, либо `null` для диапазона или неоднозначной записи. `raw_unit` сохраняет явно указанную единицу. `reported_scale` принимает `fraction` или `percent`, когда шкала установлена по источнику. Для чисел без установленной шкалы передай `null`. Поля `normalized` и итоговый `baseline` формирует Go. Если в PDF есть сопоставляемый baseline, его можно передать отдельным результатом и сослаться на него через `baseline_result_id`.
- `extracted` означает, что значение прочитано. Для него нужны `raw_value` и хотя бы один `Evidence` по записи или по `raw_value`. `present_not_extractable` подходит для явно упомянутого, но недоступного значения. `absent` подходит для явно обозначенного отсутствия в конкретной ячейке или эксперименте. Повтор найденного значения в другом месте сохраняется отдельной записью с `duplicate_of` только при совпадении результата и условий. Расхождения передавай отдельными записями.
- `Evidence` содержит `entity_type`, `entity_id` и `field`. `field=null` означает ссылку на запись целиком, `field="top_k"` — на конкретное поле конфигурации. `page` — номер страницы исходного PDF с 1. Для таблицы передай номер таблицы, строку и столбец. Для графика передай номер рисунка, а способ чтения или точность укажи в `note` результата. `fragment` — дословный фрагмент этой страницы либо `null`. Текст, собранный из разрозненных ячеек, передавай через указатели строки и столбца.
- `verification` сообщает, как проверили фрагмент. `text_match` — буквальное совпадение в текстовом слое той же страницы, `ocr_match` — совпадение в её OCR-тексте, `locator_only` — есть точный указатель на таблицу, рисунок или прямоугольник, `unverified` — фрагмент пока требует сверки. Совпадение фрагмента со страницей подтверждает его присутствие. Привязку к метрике и условиям проверяем отдельно.
- Опциональный `bbox=[x0,y0,x1,y1]` задаёт прямоугольник в долях ширины и высоты видимой страницы после поворота PDF. Начало координат в верхнем левом углу, x вправо, y вниз. Все координаты в диапазоне 0–1, `x0<x1` и `y0<y1`. `block_id` — опциональный идентификатор блока парсера.

Go отклоняет импорт целиком при неизвестной версии, сломанной ссылке, повторяющемся ID, цикле `duplicate_of` или номере вне диапазона страниц. Сомнительная шкала, неустановленная цитата и частично непрочитанный PDF представляются замечаниями для сохранённых записей.

Для известных шкал долей и процентов Go использует единицу `fraction`, для совместимых единиц времени — `ms`. Сохраняются и исходная, и нормализованная пары. Если единица или шкала не установлена, нормализованное значение остаётся пустым. Диапазон проверяется только при известном определении показателя и шкале.

## Проверка на корпусе

Архив `drive-download-20261120T125610Z-1-001.zip` содержит 21 dev-PDF с открытым эталоном `dev_gold/` и 90 test-PDF. Для первого прогона возьми два примера, сверяясь с эталоном после извлечения.

| PDF | Что проверить |
|---|---|
| `dev/D019.pdf`, стр. 5, Table 1 | Строка `DirectGen`, группа `Natural Questions`, столбец `EM`, исходное число `22.27`. Это первично переоценённый baseline. Полный заголовок столбца важен для многоуровневой таблицы. |
| `dev/D002.pdf`, стр. 8, Table II | На странице нет текстового слоя. Для `MoRSE` в `DS1` эталон даёт среднее `answer relevance=0.90` и стандартное отклонение `0.05`. Проверь OCR и сопоставление столбцов по изображению страницы. |

Сканы dev — `D002`, `D013`, `D021`. Обычные страницы извлекай из текстового слоя, страницы без пригодного текста отправляй в OCR. Если OCR не позволяет уверенно прочитать число, сохрани доступный указатель и статус `present_not_extractable` либо отметь непрочитанную страницу, в зависимости от того, виден ли конкретный результат.

## Выгрузка для проверки организаторами

Команда `python3 -m batch` формирует отдельное представление из семи CSV в порядке колонок `submission_template/schema.json`. В `publications.csv` — одна строка на PDF проверяемого набора, включая исключённые. `publication_id` равен имени файла без расширения. У исключённых статей шесть остальных таблиц не содержат строк. `null` становится пустой ячейкой, `0` сохраняется. В CSV `metric_value` и `metric_unit` берутся из той же пары, что `normalized_value` и `normalized_unit`, когда она известна. Для `source_*` выбирается источник значения, остальные источники сохраняются в JSON. Строку и столбец таблицы можно вынести в `note`. `issues.record_ids` формируется из ссылок на результаты той же публикации.

Перед сдачей прогнать `tools/check_submission.py` из архива. Например, проверяющий скрипт требует обозначение цитируемой публикации для `cited`, поэтому записи с неизвестным обозначением нужно сверить по PDF перед сдачей. Код `2` требует просмотра замечаний или источников. Для сканов предусмотрен режим `--ocr`.
