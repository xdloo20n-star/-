# PaperTrace. Контракт для фронтенда

Интерфейс принимает PDF со статьёй о RAG, показывает статус извлечения и позволяет найти результат, открыть источник и сравнить два результата. Для разработки используй JSON-примеры, затем замени их вызовами Go API. [OpenAPI 3.1](openapi.yaml) · [Примеры ответов](examples/api-mock.json)

## Запросы

Локальный адрес по умолчанию — `http://localhost:8080`. Сохраняй API origin в конфигурации фронта. Если фронт на другом origin, его адрес нужен в настройке CORS сервера. Все запросы, кроме проверки здоровья, начинаются с `/api/v1`.

| Метод и путь | Что передать и получить |
|---|---|
| `POST /documents` | `multipart/form-data`, поле `file`. Ответ `202` содержит `document_id`, `status=queued`, режим извлечения и URL исходного PDF. |
| `GET /documents` | Страница документов со статусами, свежие загрузки первыми. |
| `GET /documents/{id}` | `{document, data}`. В `data` доступны публикация, извлечённые сущности и замечания после завершения. |
| `GET /documents/{id}/file` | Исходный PDF. Для просмотрщика поддерживаются байтовые диапазоны. В документе уже есть `file_url`. |
| `GET /results` | Страница результатов. Фильтры `document_id`, `dataset_id`, `task_id`, `config_id`, `metric_name`, `has_issues`, строка поиска `q`. |
| `GET /results/{id}` | Результат с конфигурацией, датасетом, задачей, экспериментом, источниками и замечаниями. |
| `POST /comparisons` | JSON с `left_result_id` и `right_result_id`. Ответ содержит решение и причины по каждому критерию. |
| `GET /export` | JSON-выгрузка, опционально `?document_id=…`. Связи, источники, замечания и версия схемы включены. |

Списки отвечают `{items, page, page_size, total}`. Нумерация с 1, размер по умолчанию — 25, максимум — 100. Сбрасывай `page` на 1 при изменении фильтров. Фильтры применяются одновременно. Результаты идут в стабильном порядке по `result_id`. Элементы за пределами последней страницы возвращаются пустым массивом. `q` ищет по подстроке в названии публикации, метрики, датасета, задачи или конфигурации. ID в HTTP-ответах выданы сервером, используй их как строки без разбора структуры.

## Загрузка и состояния

1. Отправь файл через `FormData` и сохрани `document_id`. Браузер сам формирует заголовок multipart с boundary.
2. Пока статус `queued` или `processing`, опрашивай `GET /documents/{id}` раз в 1–2 секунды. При переходе с экрана отмени запрос и таймер. До завершения `data=null`.
3. При `completed` останови опрос. Если `publication.in_scope=false`, покажи `exclusion_reason`. Если статья в области, открой список с `document_id` и покажи состояние пустого списка при отсутствии результатов. Если `data.source_document.unreadable_pages` содержит страницы, покажи, что извлечение было частичным.
4. При `failed` останови опрос и покажи `document.failure.message`. Ошибка запроса загрузки приходит отдельно в формате `{"error":{"code":"invalid_pdf","message":"…"}}`. `400` означает ошибку параметров или тела, `413` — превышение лимита загрузки, `415` — неподдерживаемый файл, `404` — неизвестный ID.

В режиме `extraction_mode=mock` рядом с документом и результатами показывай «Синтетические данные». В сравнении режим приходит для обеих сторон. У синтетического источника показывай пример локатора как часть фикстуры, без перехода на якобы подтверждающую страницу загруженного пользователем PDF.

## Результаты и источники

- В таблице показывай метрику, конфигурацию, датасет, исходную запись и число замечаний. `normalized` содержит `{value, unit}` или `null`. При `null` оставь исходное значение без пересчёта. Сохраняй отображение нуля и используй «не указано» для отсутствующих сведений. Значения со статусом `present_not_extractable` или `absent` показывай с подписью статуса.
- В карточке покажи `result_origin` и, для цитируемой записи, `cited_publication_id` при наличии. Источник открывается через `document.file_url` на `evidence.page`, например с фрагментом `#page=5`. `file_url` можно получить из документа по `document_id`. Рядом покажи цитату, таблицу и строку/столбец или рисунок, когда они указаны. При `locator_only` или `unverified` подпиши источник «Требует сверки». При наличии `bbox` просмотрщик может подсветить фрагмент.
- `issues` содержит код правила, описание и ID связанных результатов и источников. Источник замечания разрешается по `evidence_ids`. Один результат может иметь несколько источников, в том числе для отдельных полей конфигурации.

## Сравнение

Передай два разных `result_id`. Ответ `200` может содержать любой из трёх статусов.

| Статус | Что показать |
|---|---|
| `comparable` | Данные сопоставимы. Если есть `numeric`, покажи разницу `right_value − left_value` в `unit` и предпочтительную сторону из `preferred`. |
| `not_comparable` | Известные условия различаются. Покажи причины из `criteria` со статусом `mismatch`. |
| `insufficient_information` | Для сопоставления не хватает сведений. Покажи критерии со статусом `missing`. |

Сопоставимость определяет API. Критерий со статусом `not_applicable` можно свернуть. `numeric=null` означает, что числовой разницы нет. При `preferred=unknown` можно показать разницу без выделения лучшего результата.

## Команды для интеграции

```bash
api=http://localhost:8080/api/v1
curl -F 'file=@dev/D019.pdf' "$api/documents"
curl "$api/documents/DOCUMENT_ID"
curl "$api/results?document_id=DOCUMENT_ID&page=1"
curl "$api/results/LEFT_RESULT_ID"
curl -H 'Content-Type: application/json' \
  -d '{"left_result_id":"LEFT_RESULT_ID","right_result_id":"RIGHT_RESULT_ID"}' \
  "$api/comparisons"
curl "$api/export?document_id=DOCUMENT_ID"
```
