# Короткая демонстрация CBEPKA

## Питч на 45 секунд

CBEPKA превращает статью о RAG-системе в проверяемые данные. Мы извлекаем конфигурации, датасеты, задачи и метрики, но сохраняем рядом страницу, таблицу, строку, столбец и цитату из PDF. Поэтому эксперт может проверить не только число, но и то, к какой системе и условию оно относится.

При сравнении CBEPKA проверяет критерии RAG-кейса: задачу, датасет и его версию, определение метрики и cutoff, шкалу, агрегацию и протокол оценки. Если контекста не хватает, система так и сообщает; разные эксперименты не склеиваются. Известная шкала нужна для числовой нормализации, исходная запись остаётся доступна.

На выходе — интерфейс для проверки источников и семь связанных CSV для машинной обработки. Мы проверили обработку на полном наборе из 90 тестовых PDF; технические ошибки отделены от замечаний, которые требуют экспертной проверки».

## Демонстрация за минуту

Запустите приложение в режиме Python. Для репетиции скачайте [версию статьи на arXiv](https://arxiv.org/abs/2610.29933) как `D001.pdf`. Держите обработанный экземпляр в списке документов на случай, если свежая загрузка займёт больше времени.

1. В разделе **Документы** загрузите D001 и дождитесь перехода к результатам. Найдите EM для HotpotQA и LLaMA3-8B-Instruct. Для сравнения возьмите строки RA-CoT (`.204`) и ReAct (`.268`) из таблицы 1.
2. В строке RA-CoT нажмите **К источнику**. Проверенный источник откроется на странице 6 версии arXiv. Покажите таблицу 1, строку RA-CoT и столбец EM для HotpotQA.
3. В списке нажмите число в колонке **Замечания**. Покажите предупреждение о нормализации и объясните, что без подтверждённой шкалы исходное значение остаётся без пересчёта.
4. Отметьте обе строки и нажмите **Сравнить**. Покажите решение API и объясните, каких данных не хватает для сравнения. Обратите внимание на шкалу обеих записей.
5. Вернитесь к результатам и нажмите **Выгрузить JSON**. В файле остаются данные статьи, результаты, источники и замечания.

Если у записи есть неподтверждённые источники, кнопка **Требует сверки** в её карточке ведёт к первому из них.

Для проверки перед защитой откройте **Группы** в отдельной базе с одной публикацией. Должно появиться сообщение об отсутствии подтверждённых межстатейных групп. Отдельно запустите режим `mock`, загрузите PDF и проверьте подпись **Синтетические данные** в списке и в карточке. Синтетический локатор остаётся в карточке как пример.

## Результаты проверок

- Dev: 21 из 21 PDF; для табличных значений строгий exact-match F1 — 14,34% (precision 54,01%, recall 8,27%; 451 точное совпадение). До последней правки было 436 совпадений и F1 13,89%. Это локальная оценка извлечения по опубликованным ключам организаторского dev-эталона, не оценка научной достоверности.
- Test: 90 из 90 PDF обработаны, 2 029 строк результата; структурных ошибок — 0. Проверка цитат нашла буквальное совпадение для 3 999 из 4 011 запросов.
- Проверка не сертифицирует полноту: на test осталось 2 069 замечаний для ревью, в основном неизвестные числовые шкалы и статьи без найденных результатов; 12 цитат не совпали буквально и требуют ручной проверки.

Текущий PDF-извлекатель автоматически находит в основном табличные результаты. Данные графиков и полное покрытие статей требуют отдельного извлечения и проверки.
