# Извлечение из PDF

**Ветка `team/extractor`.** Файлы `extractor/`. Для изменений формата JSON сверяйтесь с [контрактом](../docs/extractor-contract.md).

1. **D009** — начать с таблиц 1, 3 и 4. Из 252 извлечённых строк ни одна не совпала по строгому ключу. После исключения варианта метрики и агрегации из диагностического ключа совпали 144. На странице 9 сверить номер таблицы с PDF. Вариант и агрегацию записывать, если их подтверждает статья.
2. **D006** — разбирать таблицы 2 и 3, где `NDCG@5` задан в подписи, а заголовок группирует датасеты. В эталоне 350 табличных строк, в текущей выгрузке ноль.
3. **D007** — разбирать блоки датасетов и повторяющиеся столбцы EM, F1, Acc, Step и Time. Начать с Table 2, проверить перенос на Tables 7–8. Всего 743 эталонные табличные строки.
4. **D012** — извлекать полные названия метрик из легенды для `Leak`, `Stale`, `Unsup.` и переносить явно указанную шкалу. Начать с Tables 1–2, затем проверить приложения. Всего 714 эталонных табличных строк.

На каждый новый формат добавить небольшой пример с ожидаемыми значением, метрикой, датасетом, страницей и таблицей. После серии изменений прогонять все 21 `dev` PDF. Сверять число статей с результатами, строгие precision и recall и совпадения с учётом конфигурации и датасета. D001 служит контрольной статьёй с 252 строгими совпадениями в текущем прогоне.

**Готово, когда** в PR есть показатели до и после по всему `dev`, примеры новых совпадений с источниками и выход `PYTHONPATH=extractor python3 -m unittest discover -s extractor`.
